# Authentication and sessions

## 1. Passwords

- **Argon2id** preferred (`m=64MiB, t=3, p=1` as a starting point, calibrated to
  hardware), then bcrypt (`cost >= 12`) or scrypt. Never MD5/SHA-1/SHA-256 alone.
- Unique salt per user, generated by the library. Pepper only in a secret
  manager, never in code.
- Rehash on login when parameters change.
- Constant-time comparison; uniform response time and message for unknown user
  and wrong password.
- Minimum length 12, allow long passphrases (up to 128), no composition rules,
  check against breached-password lists.
- Do not impose silent truncation or email-case sensitivity on login.

```ts
// Argon2id verification with rehash-on-login
const ok = await argon2.verify(hash, password);
if (ok && argon2.needsRehash(hash, opts)) {
  await store.updateHash(userId, await argon2.hash(password, opts));
}
```

## 2. Login flow

- Rate limit by account, by IP and by combination; progressive backoff; never
  allow permanent lockout of a victim.
- Generic errors: "invalid credentials". Do not reveal whether the account
  exists, is locked or unverified.
- MFA/step-up for sensitive actions; support TOTP/WebAuthn, recovery codes
  hashed at rest.
- Passkeys/WebAuthn: verify `origin`, `rpId`, challenge and signature; store
  credential ID and public key only.
- After login: rotate the session ID, set cookies, record last-login metadata.
- After password or email change: revoke other sessions and notify the user.

## 3. Session cookies

```
__Host-sid=<opaque 128+ bits>; HttpOnly; Secure; SameSite=Lax; Path=/
```

- `SameSite=Lax` default; `Strict` for admin; `None` only with `Secure` and a
  documented cross-site requirement plus CSRF tokens.
- Idle and absolute timeouts. Rotate on privilege change. Server-side store
  with revocation (Redis/DB), not a stateless cookie with user data.
- Logout invalidates server-side and clears the cookie. "Logout all devices"
  exists.
- Never put session IDs in URLs, referrers, localStorage or analytics.

## 4. JWT

- Verify signature with a pinned algorithm allowlist; reject `none` and
  algorithm substitution.
- Validate `iss`, `aud`, `exp`, `nbf`, `iat`, and a `jti` where revocation is
  needed.
- Access tokens short-lived (5–15 min); refresh tokens rotated, stored
  server-side or in `HttpOnly` cookies, with reuse detection that revokes the
  family.
- Do not put PII or authorization decisions in unencrypted claims; the server
  still checks permissions.
- Key rotation with `kid`; never ship a private key to the client.

## 5. OAuth 2.0 / OIDC

- Authorization Code + PKCE for all clients, including SPAs and mobile.
- Exact `redirect_uri` allowlist; no wildcards, no open redirects.
- `state` bound to the session and single-use; `nonce` for OIDC ID tokens.
- Validate ID token signature, `iss`, `aud`, `exp`, `nonce`; do not trust
  `email` without `email_verified` when it grants access.
- Never accept tokens from the URL fragment or query for API calls.
- Scope minimization; consent screens show real scopes.
- Protect the callback from CSRF and from code injection/replay.

## 6. Account recovery

- Tokens: CSPRNG, single-use, short TTL (15–60 min), hashed at rest, bound to
  the account and purpose.
- Never reveal account existence; always show the same confirmation.
- Recovery link must not leak via `Referer`: use `Referrer-Policy: no-referrer`
  on the reset page and avoid third-party resources.
- Invalidate tokens after use, password change or email change.
- Notify the user of recovery attempts and completed changes.

## 7. Enumeration, brute force, credential stuffing

- Uniform status codes, bodies and timing across login, register, reset and
  invitation flows.
- Rate limits and CAPTCHA only after risk signals; monitor distributed attempts.
- Block breached passwords and known credential-stuffing patterns.
- Alert on spikes of failures per ASN/IP and on successful logins from new
  geographies.

## 8. Common findings

| Finding | Impact |
| --- | --- |
| Password reset token in URL, never expires | Account takeover |
| Session not rotated after login | Session fixation |
| JWT verified with `jsonwebtoken.decode` | Full auth bypass |
| Token in `localStorage` | XSS becomes account takeover |
| No logout revocation | Stolen session survives |
| Different error for unknown user | Enumeration |
| Unlimited login attempts | Brute force |
| `email_verified` ignored | Account takeover via unverified email |
